Product briefing - LLM_Language (internal)

Goal
Build a product using a local, self-hosted LLM. Prefer free/open-source
agent tooling. Do not depend on paid cloud APIs for day-to-day work.

Runtime
- LLM host: Linux box on the LAN
- Server: llama.cpp llama-server
- OpenAI-compatible root: http://192.168.0.50:8081/v1
- Currently loaded model: LocoOperator-4B (Qwen3 4B, Q4_K_M, 8192 context)
- Other models available on the host (only the loaded one is served):
  Agents-A1-4B, Satyr-V0.1-4B
- Auth: bearer token in Authorization header

Adopted tools
- OpenHands already runs on the server for coding work
- CrewAI 1.15 is installed on this Windows PC for small role-based crews
- Crews should stay small (1–2 agents). This 4B model is built for
  tool-calling, not large multi-agent swarms.

Constraints
- No internet is required to talk to the LLM
- If the loaded model on the server changes, update the CrewAI model=
  string to match or requests return 404
- To rotate the API key later: edit LLAMA_API_KEY in
  /etc/default/llama-server on the Linux host, then
  systemctl restart llama-server, and update the key in the LLM() call

Near-term product questions
1. What should the first user-visible feature be?
2. Should we keep CrewAI as a thin orchestration layer only, and leave
   coding to OpenHands?
3. How do we switch models without breaking existing crews?
