# AI project instructions — LLM_Language

Author: Matthew Schinkel

## Purpose
This project explores using a local LLM with free/open-source agent tooling to help build a product.

## Working rules
- Prefer local, self-hosted, open-source tooling over paid cloud APIs.
- Do not install hacks or workarounds; all fixes should be proper.
- Keep progress.md current: Highlights, TODOs, previous issues, scripts.
- Follow-up items always go in progress.md TODOs.
- When renaming variables, functions, or procedures, log them in name_changes.md.
- Review files in ai_docs/ at the start of work.
- When working with .css files, bump the version after edits.
- Do not restore from backup without asking.
- Never `git checkout HEAD` / reset / force-push without the Architect's (R1) OK; take a backup first. R1 is autonomous and approves these itself (no human gate); R6 logs the operation to the dashboard. A local git repo is maintained for the agents to use.
- When using Windows PowerShell, do not use `&&` with commands.
- **Build path (2026-09-11):** Cursor implements Knot against phase specs. The 4B CrewAI autobuild is abandoned for implementation (see `fixes/fix_stop_crew_cursor_drives.md`).

## Local LLM assumption
The user already runs a local LLM (Ollama, LM Studio, llama.cpp, or another OpenAI-compatible endpoint). Agent tools should connect to that endpoint instead of cloud providers unless the user asks otherwise.
